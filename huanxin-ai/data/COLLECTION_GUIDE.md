# 多领域数据采集清单（COLLECTION GUIDE）

目标：为「专属 AI」积累高质量、可溯源、许可证干净的语料。

核心原则：**第一方优先；少量高质量胜过量大低质；每条数据可回溯来源；不收集 PII。**

---

## 通用规则（所有领域适用）

- [ ] 每条数据能说清来源（文件 / 链接 / 自有产出）。
- [ ] 去掉 PII（手机号、身份证、密码、客户真名）—— 训练数据泄露很危险。
- [ ] 中文优先；混英文时标注语境。
- [ ] 一个文件讲一件事，勿把不相关文档拼一起。
- [ ] 体积：起步几百条即可跑通；要"像你"，建议每领域 ≥ 1000 条高质量样本。
- [ ] 领域分布均衡（避免某一域占比 > 70% 导致偏科）。

---

## 领域清单

### 1. general/ 通用中文对话
- **来源**：你对 AI 的日常期望回答、FAQ、产品说明。
- **格式**：`.md`（会被派生成问答）或 `.jsonl`（人工写好的对话）。
- **目标**：让模型语气、价值观贴近你。
- 示例见 `general/example_intro.md`。

### 2. legal/ 法律
- **来源**：合同条款、法规摘录（注明出处与版本）、常见咨询问答。
- **注意**：必须标注「非法律意见」免责；法规数据带生效日期与 jurisdiction。
- **目标**：领域准确性，不胡编。
- 示例见 `legal/example_contract_terms.md`。

### 3. medical/ 医疗
- **来源**：健康科普（权威出处）、用药说明（注明来源）。
- **注意**：必须标注「仅供参考，不替代医生诊断」；禁止生成诊断结论。
- **目标**：科普准确性。
- 示例见 `medical/example_faq.md`。

### 4. code/ 代码
- **来源**：你写过的函数、报错解决记录、技术笔记。
- **格式**：`.md`（代码块 + 解释）或 `.jsonl`（`{instruction, output}`）。
- **目标**：复刻你的编码风格与常用技术栈。
- 示例见 `code/example_snippets.md`。

### 5. customer_service/ 客服
- **来源**：真实对话脱敏导出、标准应答话术。
- **格式**：`.jsonl`，ShareGPT 或 Alpaca。
- **目标**：一致的应答规范与语气。
- 示例见 `customer_service/example_dialog.jsonl`。

### 6. personal/ 个人风格（最关键）
- **来源**：你的笔记、思考、写作样本、决策记录。
- **目标**：让模型"像你"。这是最不可替代、最"专属"的部分。
- 示例见 `personal/example_notes.md`。

---

## 合法获取外部数据的渠道（许可干净）

- GitHub 上的开源指令数据集（搜 `instruction-tuning chinese`、`alpaca-zh`、`sharegpt`）。
- ModelScope / HuggingFace 的中文指令数据集（注意各自 license）。
- 你自己的业务系统导出（脱敏后）。
- ⚠️ 不要直接爬取未授权内容；不要使用明确禁止商业 / 再训练的许可证数据。

---

## 质量自检

- [ ] 抽样 20 条人工读一遍，无明显错误 / 乱码 / 重复。
- [ ] 领域分布均衡。
- [ ] 跑一遍 `python train/data_prep.py --input data/raw --output data/prepared`，
      确认 `prepared/train.jsonl` 行数符合预期。
