## P2 问题陈述

### 当前 AI 系统的三大痛点

1. **单点脆弱**：单个模型的幻觉和偏见无法自我纠正
2. **静态能力**：模型能力出厂即固化，无法随任务优化
3. **集成孤岛**：LLM、RAG、工具调用、多模态各成体系，缺乏统一编排

> "AI 不应是一个全知全能的 oracle，而应是一个能自我纠错、协作进化的团队。"

### 我们解决的问题

- 如何让多个 AI Agent 协同工作而非互相冲突？
- 如何让系统在运行中自动进化而非人工调优？
- 如何在一个框架内融合 LLM / RAG / 多模态 / 工具调用？

## P5 核心创新（一）：自进化 + 自愈

### 大臣进化引擎

```
任务执行 → 结果分析 → 交叉进化 → 突变淘汰 → 能力提升
```

- 基于 **遗传算法 + 粒子群优化** 的混合进化策略
- 含金量（merit_score）追踪大臣质量
- 自动淘汰低效大臣，保留优质基因

### 自愈机制

```
故障检测 → 根因定位 → 策略选择 → 自动修复 → 验证恢复
```

- 8 种故障场景自动恢复（超时/内存/State/DB/Python/Config/API/网络）
- 三级诊断：快速检测 → 深度分析 → 专家规则

> **实测数据**：自愈成功率 85%+，平均恢复时间 < 3 秒

## P6 核心创新（二）：辩论共识 + 混合检索

### 多智能体辩论共识

5 种共识策略：

| 策略 | 适用场景 | 特点 |
|------|---------|------|
| MajorityVote | 客观题 | 快速、公平 |
| WeightedVote | 专业领域 | 专家意见权重更高 |
| DebateRound | 复杂推理 | 多轮辩论修正答案 |
| BestOfN | 高精度需求 | 取置信度最高答案 |
| SynthesisConsensus | 开放式问题 | LLM 综合所有意见 |

- 交叉评审机制：大臣互评对方输出
- **减少 70% 多智能体冲突**

### RAG 混合检索

- **Dense + Sparse 混合检索 + RRF 融合 + LLM Rerank**
- 向量检索（ChromaDB）+ 关键词检索（BM25）
- 知识库自动构建与增量更新

## P8 应用场景

### 场景一：政务智能问答

- 多源政策文件 RAG 检索
- 多大臣交叉验证答案准确性
- 自愈机制保证 7×24 服务稳定

### 场景二：企业知识管理

- 内部文档自动索引 + 混合检索
- 多模态：支持图文混排问答
- 大臣进化：越用越懂企业业务

### 场景三：智能客服编排

- Router 自动分流意图（售前/售后/投诉）
- 12 种内置工具覆盖常见客服操作
- 辩论共识确保回复质量

### 场景四：科研辅助

- 多源论文检索 + 文献综述生成
- 交叉评审减少 AI 幻觉
- 代码执行沙箱安全运行实验
