| 项 | 内容 |
|---|---|

## 2. 产品定义

### 2.1 一句话定位

将 emperor-core 从「单用户 admin-only 演示」升级为「支持注册登录、个人数据隔离，并具备文件上传、真实联网搜索、图文识别三大能力」的多用户自进化 AI 系统。

### 2.2 产品目标

1. **开放多用户注册**：任何访客可注册独立账号，登录后对话/会话数据按 user_id 完全隔离，互不可见。
2. **补齐文件上传**：提供前端上传入口 + 后端安全存储，用户可上传文件并交给系统处理。
3. **落地真实联网搜索**：将现有「离线占位」的 web_search 域替换为真实 HTTP 搜索，返回真实、可溯源的联网结果。
4. **打通图文识别**：为已有 `VisionProcessor` 引擎补上 HTTP 入口，并解决视觉模型选型，支持图片→文本理解。
5. **权限与配额可控**：建立管理员 vs 普通用户的权限边界，对用量/上传/搜索设置可配置限额，避免资源滥用。

### 2.3 用户故事

**新用户**
1. 作为新用户，我希望能在登录页一键注册账号，以便无需管理员手工开号即可开始使用。
2. 作为新用户，我希望登录后只能看到自己的对话历史，以便我的私人对话数据不被他人查看。

**老管理员**
3. 作为老管理员，我希望注册开关从「硬编码关闭」改为「可配置」，以便按部署形态决定是否开放注册。
4. 作为老管理员，我希望拥有查看/管理所有用户、重置密码、封禁账号、调整配额的后台能力，以便治理多用户环境。
5. 作为老管理员，我希望所有文件上传、联网搜索、视觉识别调用都记录在案（日志/账本），以便审计和成本核算。

**普通用户**
6. 作为普通用户，我希望在聊天中上传文件（文档/图片等），以便系统能读取其内容辅助问答。
7. 作为普通用户，我希望在需要时开启联网搜索，以便获得基于实时互联网信息的回答（而非离线占位答案）。
8. 作为普通用户，我希望上传图片后系统能识别图片中的文字/内容，以便用「图文」方式提问。

## 3. 技术规范

### 3.1 需求池

#### P0（必须，本次上线核心）

| 编号 | 需求 | 验收标准 |
|---|---|---|
| P0-1 | 开放注册：将 `court_api.py` 中 `/api/auth/register` 的硬编码 403 改为调用 `auth_store.create_user()`，注册开关可配置 | 新用户通过用户名+密码注册成功；重复用户名被拒绝；密码经 pbkdf2 加盐哈希存储；`public_paths` 已放行（已具备） |
| P0-2 | 多用户数据隔离确认 | 登录态下 `conversations`/`messages` 接口仅返回当前 user_id 数据；跨用户访问返回 404/403，无法枚举他人会话 |
| P0-3 | 文件上传：新增上传路由 + 前端上传入口 | 用户可上传文件并返回文件引用；后端校验类型/大小；文件落盘至持久化卷（`/app/data/uploads`），重启不丢失 |
| P0-4 | 真实联网搜索：将 `task_router.py` 的 web_search 域接入真实 HTTP 搜索后端 | 输入查询返回真实、含来源 URL 的结果；无网络/无 key 时优雅降级并明确提示 |

#### P1（重要，紧随其后）

| 编号 | 需求 | 验收标准 |
|---|---|---|
| P1-1 | 图文识别 HTTP 入口：为 `VisionProcessor` 补上传/图片 URL 入口，对接所选 vision 模型 | 上传图片或传图片 URL 后返回结构化文字描述；非视觉输入模型不报致命错误 |
| P1-2 | 管理员后台：用户列表、重置密码、封禁/启用、配额管理 | 管理员可查看所有用户、调整配额、封禁用户；普通用户无权限调用 |
| P1-3 | 配额与限流：按用户限额（对话次数、上传大小、搜索次数） | 超限用户收到明确提示；配额可在配置中调整 |
| P1-4 | 前端入口补齐：上传按钮、联网搜索开关、图片识别结果展示 | 入口可见、可用、交互状态清晰（详见 3.2） |

#### P2（可选，体验增强）

| 编号 | 需求 | 验收标准 |
|---|---|---|
| P2-1 | 上传文件类型扩展与预览 | 支持更多格式（PDF/图片/文本），上传后可见预览/缩略 |
| P2-2 | 搜索/视觉结果溯源展示 | 结果卡片展示来源链接、生成时间、引用 |
| P2-3 | 用量可视化 | `/api/me` 用量在个人页可视化展示 |
| P2-4 | 邀请码/邮箱验证注册 | 可选开启邀请码或邮箱验证，控制注册质量 |

### 3.2 UI 设计要点

**注册/登录**
- 复用现有 `chat_dashboard.py` 中的登录/注册模态框（已存在）。
- 注册模态框：用户名 + 密码 + 确认密码；前端做非空/强度/二次一致校验；注册成功自动登录跳入主界面。
- 未登录访问主界面 → 重定向到登录态；登录态缺失 token 时统一回到登录页。

**上传按钮**
- 主聊天输入框旁加「📎 上传」图标按钮，点击触发文件选择器。
- 上传中显示进度/loading；成功后消息区显示文件卡片（文件名、大小、类型图标）。
- 上传失败（超限/类型不允许）在卡片或 toast 明确提示原因。

**图文识别结果展示**
- 用户发送图片（或图片 URL）后，消息区以「图片缩略图 + AI 返回的文字识别结果」组合展示。
- 识别中显示「正在识别…」；识别失败（模型不支持视觉）给出可读提示，而非 500。

**联网搜索开关**
- 聊天输入区增加「联网搜索」开关（默认关闭）。
- 开启时视觉高亮（如开关变色/加「已开启联网」标签），并在返回结果中展示来源链接。
- 搜索失败（无 key / 网络异常）在消息内明确说明「联网搜索不可用，已回退本地回答」。

### 3.3 待确认问题（本次 PRD 关键）

1. **图文识别的 vision 模型选型（阻塞项）**：当前唯一有额度的 NVIDIA NIM `meta/llama-3.1-8b-instruct` 是纯文本模型、不支持视觉输入。需确认换用哪个 vision 模型/服务（如 NVIDIA NIM 的 `nvidia/llama-3.2-vl` 或 `nvidia/neva-22b`、OpenAI `gpt-4o`、Qwen-VL、本地开源 VL 模型等），并明确其 API key、额度与成本。

2. **联网搜索的 API 选型**：免费 DuckDuckGo（无 key、有限制）／自建 SearXNG（需额外容器、隐私好）／付费 SerpAPI·Bing（有 key、结果稳定、按次计费）。需确认选哪个，以及各自 key 与预算上限。

3. **文件上传的存储方案与限制**：确认存本地卷 `/app/data/uploads`（推荐）还是对象存储；允许的文件类型清单；单文件大小上限；存储总配额；以及安全校验（MIME/扩展名白名单、文件内容嗅探、文件名清洗、防路径穿越）。

4. **多用户权限与配额**：普通用户 vs 管理员的权限边界（管理员是否可看他人对话、是否可封禁、是否可调整配额）；是否对普通用户限额（对话/上传/搜索次数与容量）；注册开放策略（完全开放 vs 邀请码 vs 管理员审核）。

5. **成本与鉴权归属**：文件存储、视觉识别、联网搜索产生的成本如何分摊/计费，是否接入现有 `token_ledger` 用量账本统一计量。
